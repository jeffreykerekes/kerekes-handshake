# Kerekes Handshake — Folder Architecture

This is a quick reference for how to organize your website folder before deploying.
Everything goes in one folder. The subfolder names matter — do not rename them.

```
your-website/                       ← Your main folder (deploy everything inside here)
│
├── index.html                      ← Your existing home page (add a link to /audit.html)
├── audit.html                      ← AI audit entry page (the main new page)
├── query/
│   └── index.html                  ← Full audit portal (served at /query/)
│
├── evidence/                       ← Put ALL your PDFs and .txt files here
│   ├── your-document.pdf
│   ├── your-document.txt           ← Generated from PDF by pdftotext
│   └── index.html                  ← Evidence vault directory page
│
├── claims.json                     ← Claims registry (stays at root)
├── site_manifest.json              ← Generated by seal-and-deploy.sh
├── site_manifest.json.asc          ← PGP-signed version (generated by seal-and-deploy.sh)
│
├── _worker.js                      ← Cloudflare Worker (use provided version, do not rename)
├── _redirects                      ← Cloudflare URL rules (optional)
├── _headers                        ← Cloudflare static headers (optional)
├── wrangler.toml                   ← Cloudflare project config
│
├── seal-and-deploy.sh              ← Run this to sign and deploy
│
└── llms.txt                        ← Short AI context file (optional)
```

## Rules

**These files must be at root — they cannot be in a subfolder:**
- `_worker.js`
- `wrangler.toml`
- `claims.json`
- `site_manifest.json.asc`

**These files go in `/evidence/` — not at root:**
- All PDFs
- All `.txt` sidecar files (matching names, `.txt` extension)

**Your HTML pages can go anywhere**, but if you put them in subfolders, use absolute paths
in `claims.json` — write `/evidence/file.pdf` not `../evidence/file.pdf`.

## Linking to the Audit Page

If you already have an `index.html`, add a link to `/audit.html` — don't replace it.
Example: `<a href="/audit.html">Verify This Proposal</a>`

If you have no existing `index.html`, add a simple one that redirects:
```html
<!DOCTYPE html>
<html><head>
<meta http-equiv="refresh" content="0; url=/audit.html">
</head></html>
```

## What seal-and-deploy.sh Creates

Running `./seal-and-deploy.sh` automatically creates:
- `.txt` sidecars for any PDFs missing them (in `/evidence/`)
- `site_manifest.json` (SHA-256 hashes of all files)
- `site_manifest.json.asc` (PGP-signed version of above)

It does NOT create `claims.json` or any HTML files — those must exist first.
